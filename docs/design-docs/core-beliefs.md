# 핵심 설계 원칙 (Core Beliefs)

> FALCON-1 프로젝트의 모든 의사결정은 이 원칙을 기반으로 한다.
> 원칙과 충돌하는 작업이 있으면, 원칙을 우선한다.

---

## 1. 에이전트가 볼 수 없는 것은 존재하지 않는다

- Slack, Google Docs, 구두 합의에 의존하지 않는다.
- **모든 결정, 계획, 변경 사유는 `docs/`에 기록한다.**
- AI 에이전트가 읽을 수 없는 매체에 저장된 정보는 존재하지 않는 것과 같다.
- 실행 계획은 반드시 `docs/exec-plans/active/`에 마크다운으로 작성한다.

## 2. 문서는 목차지 백과사전이 아니다

- `AGENTS.md`는 100줄 이내로 유지한다.
- 각 문서는 **한 가지 역할**만 수행한다.
- 상세 내용은 하위 문서에 위임하고, 상위 문서는 링크만 제공한다.
- 문서가 비대해지면 즉시 분할한다.

## 3. 아키텍처 제약은 린터로 강제한다

- "이렇게 하지 마세요"라는 문서만으로는 부족하다.
- **ruff, clang-tidy, verify-task.sh로 규칙을 코드 수준에서 강제한다.**
- 의존성 방향 위반, 파일 크기 초과는 린터/스크립트가 차단한다.
- 수동 리뷰에만 의존하는 규칙은 반드시 깨진다.

## 4. 가비지 컬렉션은 지속적으로 한다

- 매주 `scripts/doc-gardening.sh`를 실행하여 오래된 문서를 정리한다.
- 30일 이상 수정되지 않은 `docs/exec-plans/active/` 파일은 `completed/`로 이동하거나 삭제 검토한다.
- 중복 코드, 미사용 import, 죽은 분기는 발견 즉시 제거한다.
- 기술 부채는 쌓이기 전에 처리한다.

## 5. 수정 비용은 저렴하게 유지한다

- PR(커밋)은 짧고 빠르게 — 한 번에 하나의 변경만 포함한다.
- 완벽을 추구하기보다 **빠른 반복**을 우선한다.
- 롤백이 쉬운 구조를 유지한다 (작은 커밋, 명확한 스코프).
- 500줄 초과 파일은 존재해서는 안 된다 — 분할 비용을 항상 낮게 유지한다.
