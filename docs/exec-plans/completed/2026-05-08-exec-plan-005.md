# 실행 계획: validation-environment-recovery

> 생성일: 2026-05-08 | 브랜치: chore/archive-exec-plans-pr8

## 목표
`scripts/verify-task.sh`에서 현재 경고로 넘기는 Python 테스트 import 문제와 ROS build 의존성 문제를 재현 가능하게 복구한다.

## 접근법
먼저 `pytest` 수집 실패 원인을 패키지 경로/설치 구조 기준으로 분리하고, 이어서 `falcon1_interfaces` 빌드 실패를 일으키는 `em` 의존성 누락 경로를 확인한다. 수정은 환경 설정과 패키지 경계에 한정하고, 검증은 기존 표준 스크립트로 닫는다.

## 단계별 계획
- [x] 1. `pytest` 수집 실패 재현 및 `falcon1_perception` / `shoppinkki_perception` import 경로 원인 확인
- [x] 2. 테스트/패키지 구조 수정 또는 설정 보강으로 Python import 문제 해결
- [x] 3. `falcon1_interfaces` 빌드 실패 재현 및 `em` 의존성 누락 위치 확인
- [x] 4. ROS/Python 환경 설정 또는 문서 보강으로 build 의존성 문제 해결
- [x] 5. `bash scripts/verify-task.sh` 재실행으로 검증
- [x] 6. 결과를 실행 계획과 관련 문서에 기록

## 완료 기준
- `python -m pytest src/ --ignore=src/openarm_ros2 -q`가 수집 단계에서 실패하지 않는다.
- `colcon build --symlink-install` 또는 관련 패키지 빌드가 `em` 모듈 누락 없이 재현 가능하게 동작한다.
- `bash scripts/verify-task.sh` 실행 결과에서 현재 두 환경 경고의 원인과 상태가 명확히 정리된다.

## 제약 사항
- `src/openarm_ros2/` 서브모듈은 수정하지 않는다.
- 시뮬레이션/실기체 관련 동작은 수행하지 않는다.
- 환경 수정이 시스템 범위 설치를 요구하면 사용자 승인 후 진행한다.

1~2시간
