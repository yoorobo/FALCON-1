# Codex 상세설계 뼈대 및 작성 계획 수립 프롬프트

> **사용 안내:** 아래 내용(코드 블록 안의 전체 텍스트)을 복사하여 Codex(또는 새 세션)에게 전달하세요. 
> 이 프롬프트는 우리가 확정한 SR과 기술조사 자료(PDF 등)를 매핑하여, 완벽한 아키텍처 및 상세설계 작성 로드맵을 뽑아내도록 설계되었습니다.

```markdown
너는 고도화된 자율주행 양팔 로봇(Bimanual Mobile Manipulator) 시스템 아키텍트이자 수석 소프트웨어 엔지니어인 'Codex'야.
우리는 현재 FALCON-1 프로젝트의 요구사항 분석(UR/SR)을 완료하고, 본격적인 상세설계(Design Docs) 단계로 진입하려고 해.

너의 목표는 확정된 시스템 요구사항(SR)과 사전에 조사된 기술 스택(Technology Research) 자료를 철저히 분석하여,
앞으로 작성해야 할 모든 상세설계 문서(SA, IS, SM 등)의 **작성 순서, 문서별 역할, 그리고 구체적인 뼈대(목차와 주요 구성 요소)를 포함한 마스터 플랜 보고서**를 수립하는 거야.

## 1. 분석해야 할 입력 자료 (반드시 먼저 정독할 것)

1. **시스템 요구사항 (SR)**
   - 경로: `docs/requirements/system_requirements.md`
   - 내용: 상태 전환 조건, 속도 제한, 예외 처리 등 상세설계가 준수해야 할 논리적/정량적 정책 (What/When)
2. **경계선 분석 보고서**
   - 경로: `docs/requirements/_analysis/shoppinkki_design_boundary_analysis.md`
   - 내용: SR과 상세설계(How)를 어떻게 분리할 것인가에 대한 5대 설계 원칙 (기술 종속 금지, 인터페이스 위임 등)
3. **기술 조사 자료 (Technology Research)**
   - 경로: `docs/references/Technology -Research/` 하위의 PDF 자료 전체
   - 내용: 미들웨어, 비전, 매니퓰레이션, 안전, 음성 등 FALCON-1에 실제 적용할 구체적인 알고리즘, 라이브러리, 하드웨어 기술 스택 명세

## 2. 작업 지시 (Tasks)

위 자료들을 종합하여 다음 내용이 포함된 **[FALCON-1 상세설계 마스터 플랜 보고서]**를 작성해줘.

### Task 1: SR - 기술 스택 매핑 분석
- SR의 5개 주요 카테고리(호출통신, 위치추종, 공구입출고, 공구전달, 안전)별로, 기술조사 자료(PDF)에 명시된 어떤 구체적 기술(오픈소스 패키지, 알고리즘, 프로토콜)이 매핑되어 문제를 해결하는지 표로 정리해.
- 예: [SR_A01 음성 인지] ➡️ [G-HRI-음성.pdf의 Whisper 모델 기반 로컬 STT] ➡️ 위임 문서: Interface Specification

### Task 2: 상세설계 문서 작성 순서 및 전략 수립
시스템의 의존성을 고려하여, 아래 7가지 핵심 상세설계 문서를 어떤 순서로 작성해 나갈지 로드맵을 제안해.
왜 이 순서로 작성해야 하는지 타당한 이유를 함께 명시해.
*대상 문서:*
1. SA (System Architecture): 전체 컴포넌트 및 노드 구성도
2. IS (Interface Specification): ROS 토픽, 서비스, 포트 명세
3. SM (State Machine): 로봇 전역 상태 전이 및 횡단 변수
4. MS (Manipulation Sequence): 양팔 역운동학 및 핸드오버 파이프라인
5. PFL (Safety PFL Spec): ISO 10218-2 기반 속도/힘 제한 로직
6. BT (Behavior Tree): 예외 처리 및 복합 임무 흐름
7. ERD (Entity-Relationship Diagram): 데이터 및 공구 메타데이터 스키마

### Task 3: 문서별 구체적 뼈대(Skeleton) 도출
제안한 순서대로, 각 문서가 포함해야 할 구체적인 목차(H2, H3 레벨)와 다루어야 할 핵심 키워드를 작성해.
- 각 문서의 뼈대에는 **반드시 어떤 SR 항목(SR ID)을 위임받아 처리하는지 매핑 정보**가 포함되어야 해.
- 기술조사 자료에서 추출한 구체적인 기술명(ROS 2 Jazzy, 특정 라이브러리명 등)이 뼈대 안에 명확한 설계 요소로 드러나야 해.

## 3. 출력 형식 및 제약사항
- 최종 출력은 하나의 완성된 마크다운 마스터 플랜 보고서 형태로 출력해줘.
- 내용이 길어지더라도 절대로 생략이나 말줄임표(...)를 사용하지 말고 끝까지 상세히 작성해.
- SR의 내용은 시스템 정책(규칙)으로, 기술 조사 자료의 내용은 구현체(무기)로 삼아 이 둘을 완벽하게 결합하는 것이 핵심이야.
```
